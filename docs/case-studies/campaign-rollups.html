Turnkey Campaign Reporting System

  • Built solo in under 40 hours
  • Platform I had never used
  • 2026
  • Sole builder

The situation

A client account needed weekly business review (WBR) reporting stood up from scratch. The source system was Zendesk — a platform I had zero prior experience with. No existing pipeline, no template, no second analyst.

And a hard adoption window: the reporting date had been committed to the client long before, the account manager was about to leave on vacation, and he was new — presenting numbers from a self-built workbook that hadn't survived review. I needed a working system and his buy-in before he left, or the client kept getting bad data.

Constraints

  • Foreign system. I had never built anything out of Zendesk before this project.
  • One person. No data team, no engineer. Whatever I designed, I also had to run — and then hand off.
  • Growing portfolio. This couldn't be a one-off; it had to be the pattern for every future campaign added to the book.

What I built

A controlled reporting system, not a spreadsheet. The weekly operating loop for whoever runs it is three steps:

  1. Paste the export. Raw Zendesk reports drop into dedicated Raw tabs, untouched.
  2. Update the date. One control-panel change cascades through every rollup, trend, and deck label via named ranges.
  3. Validate the data. A QA tab runs reconciliation, duplicate detection, and mapping coverage — unmapped values surface as loud UNMAPPED failure states instead of silently corrupting rollups.

Shipped with a README tab, an archive/change log, and a step-by-step production SOP so a replacement user can run the full weekly cycle without me.

See the rollup run

This is the roll-up view rebuilt as a live component — the same shape I ship in Excel. Pick an account, switch weekly to monthly, or move the start period; every cell and trend recomputes. All accounts, numbers, and sources below are invented for this demo; the real workbooks stay private.

Why it matters

Most reporting breaks because logic lives in scattered formulas only the author understands. This treats reporting as a product: inputs quarantined, transformations inspectable, failure states loud, and the refresh cost of a new week is one date change. When the vendor changes its export format — which vendors do — the fix is one transform layer, not fifty slides.

Impact

  • < 40 hoursfrom zero platform experience to production, one person, soup to nuts
  • < 30 minweekly refresh (about an hour for an account manager with full validation) — replacing several hours a day, all week, of manual prep
  • 7 of 9accounts run on the rollups engine today (remaining two in integration) — across Zendesk, Five9, Dialpad, and Salesforce sources
  • 9 of 9accounts run on the business report deck it feeds

Handoff-ready by design: any analyst can rebuild a client WBR without touching formula logic.

Artifacts

  • Reporting-system requirements brief — control variables, acceptance criteria, and operating constraints
  • Synthetic data dictionary and reporting views — source fields, validation states, and safe sample values
  • UAT checklist and production SOP — publish gates, exception handling, and handoff steps
